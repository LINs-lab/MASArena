## Key Discussion Points

### System Evaluation and Cost Considerations
- **System Evaluation Design**: System-level evaluation design, including important Metrics, System monitoring, and result profiling.
- **Single vs. Multi-agent Tradeoffs**: Considering local Multi agent capacity and workload, while agent numbers are typically specified when given a workflow.
- **Resource Control**: Tao LIN and others suggested that there's no immediate need to consider resource constraints and workload-related complex issues, as these are separate topics.
- **Model Deployment Costs**: The team discussed unifying API token costs with local deployment inference costs, suggesting they could initially reference transit stations or Open Router price tables for simple quantification.

### Multi-Agent System Evaluation Metrics
- **Token Cost Calculation**: Need to obtain the cost per token, using the mapping table directly while ignoring accuracy issues, and consider how to calculate actual token costs for multi-agent systems.
- **Inference Speed Estimation**: Consider using model size to estimate inference speed, or estimating inference latency through model parameters and hardware specifications. Alternatively, obtain concurrency data from platform providers.
- **Model Parameter Impact**: Changes in model architecture and activation parameter quantities affect inference speed, but using model size to estimate inference speed can serve as an initial proof method, with parameter ratio adjustments to support conclusions.
- **Task Benchmark Scope**: Six datasets corresponding to three major task categories have been integrated, but this may not be sufficient. Need to consider more difficult tasks or simulation-type tasks, with a focus on problem-solving.

### Necessity and Efficiency of Multi-Agent Systems
- **Task Difficulty Considerations**: Previous work focused on increasing task difficulty, with MAS showing better performance on difficult tasks. For new scenarios, need to consider whether to focus on difficulty or multiple stylistic scenarios.
- **Dataset Enumeration**: For existing TA scenarios or tasks, corresponding datasets should be fully enumerated. New scenarios that fall within the task-solving domain can be added, focusing initially on tasks and datasets, without considering different scenarios for tasks.
- **MAS Advantage Scenarios**: MAS performs better than single agents in certain scenarios, such as NODE failures. These scenarios need consideration.
- **Knowledge Density Focus**: Knowledge density is easily understood and of concern to many. Explaining why multi-agent systems are needed instead of single-agent systems represents a significant contribution.
- **Traditional Tasks Priority**: Initially focus on traditional multi-agent tasks, listing traditional Benchmarks and Manus tasks, to see if they can be migrated to the setup for analysis.
- **Task Conversion Attempts**: Collect test datasets or tasks for single-agent systems, apply simple filtering, and see which ones can be run on multi-agent systems.
